# 代码审查

按以下顺序审读用户提供的代码，输出一份结构化审查报告。

## 步骤

1. **读懂意图**：先概括这段代码要做什么、输入输出是什么。如果不确定，先向用户确认，不要臆测。
2. **正确性**：找出会导致错误结果的逻辑问题——边界条件、空值、类型、并发、资源泄漏、错误处理缺失。
3. **安全**：检查注入、越权、敏感信息泄露、不安全的依赖或输入校验缺失。按严重程度排序。
4. **可维护性**：指出命名不清、重复代码、过深嵌套、职责混杂之处，并给出具体改法。
5. **风格**：对照常见规范，只提真正影响可读性的点，不纠结个人偏好。

## 输出格式

- **结论**：一句话总体判断（可合并 / 需修改 / 有阻断性问题）。
- **问题清单**：每条包含「位置、问题、影响、建议」，严重问题排前。
- **正面反馈**：至少提一处做得好的地方。

只对用户明确给出的代码做审查；除非被要求，不要重写整段代码。
