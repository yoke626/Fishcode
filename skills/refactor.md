# 安全重构

目标是「行为不变、结构更好」。任何对外部行为的改变都属于 bug，不是重构。

## 步骤

1. **建立基线**：先确认现有行为；有测试就指出如何用测试兜底，没有就建议先补关键测试或说明风险。
2. **小步走**：每次只做一类改动（如先提取函数，再消除重复），每步都可独立验证。
3. **常见手法**：提取函数/变量、消除重复、简化条件、拆大函数、让命名表意。
4. **避免**：顺手改功能、调整对外接口、改动超出用户要求范围、为了「炫技」引入不必要的抽象。

## 输出

- 说明重构的目标与改动点清单。
- 给出重构后的代码，并对每处关键改动注明动机。
- 明确指出任何可能影响行为的地方（即使很小），让用户决定。
