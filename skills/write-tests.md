# 编写测试

为用户的代码编写测试，优先保证「能抓住回归」而非单纯追求覆盖率数字。

## 原则

1. **先问清框架**：确认测试框架和断言风格（如 Jest、Vitest、pytest）。不确定时选项目里已经在用的。
2. **覆盖分层**：正常路径、边界值（空、零、最大最小）、异常与错误处理、关键分支。
3. **独立与可读**：每个用例只验证一件事，命名写清楚「测什么、期望什么」，避免共享可变状态。
4. **可维护**：优先表驱动/参数化测试消除重复；对难以测试的依赖使用替身（mock/stub），但不要过度 mock。

## 输出

给出可直接运行的测试代码，并附一句说明每个用例覆盖的场景。若测试需要额外的夹具或配置，一并给出。不修改被测代码本身，除非其明显不可测，此时先说明再建议。
