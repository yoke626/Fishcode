# 解释代码

面向「需要真正理解代码」的读者解释，而不是逐行翻译。

## 做法

1. **整体**：先用一两句话说明这段代码的目标和所处上下文。
2. **流程**：按执行顺序讲清主要路径，突出关键分支和数据流向。
3. **关键点**：解释核心算法、数据结构或设计决策，以及为什么这样写。
4. **易错点**：指出容易误解或容易出 bug 的地方。

## 风格

- 用比喻帮助理解抽象概念，但不要为了生动牺牲准确。
- 先讲「是什么、为什么」，再讲「怎么做」。
- 对用户可能不熟悉的术语给出简短定义。
- 不确定的行为不要编造，直接说明「这里需要确认」。
